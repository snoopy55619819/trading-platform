Trading Platform: Current Implementation (MVP)

To keep scope manageable the broker runs as one backend process and the exchange as one binary.

Key

  • Order plane: private, request/response
  • Market data plane: public broadcast
  • Library linked in
  • Deployable process
  • Module inside one process
  • Library
  • Datastore
  • Company boundary

Legend

#ElementWhat it does
1webStatic bundle, not a server. Calls backend for orders and positions, market-data for prices, and joins the two itself, so the backend has no market data dependency.
2backendOne process, four modules: api (auth, no business logic), oms (pre-trade risk and order lifecycle), ledger (double-entry books), fix (session to the exchange). Merged because a buying-power check and the order write must be one transaction. Single instance: a FIX session is a stateful singleton.
3broker-dbThe security master, the double-entry ledger, and users, orders, their event history and the FIX session state.
4Order (edge)FIX 4.4 over TCP. The broker is the initiator (TypeScript), the exchange the acceptor (Rust): two independent implementations sharing only the dictionary.
5gatewayThe exchange's door. Session sequence numbers, then tick size, lot size, price band and duplicate ClOrdID checks before the engine sees anything. Conformance-tested against QuickFIX/Go, including a SIGKILL and recovery by resend.
6exchange-dbFIX session state, so sequence numbers survive a restart. The exchange's own database, never a schema in the broker's.
7fix-coreLibrary, not a server: FIX codec, data dictionary and session state machine. Has never heard of an order book.
8matching-engineThe market: price-time priority over an in-memory book, about 0.2 µs per match at the median. Feeds both planes, so it straddles the divider.
9journalAppend-only log, written before each command is applied. Recovery is replay, which rebuilds a byte-identical book; a torn final write from a crash is dropped safely.
10ExecutionReport (edge)The private result: account, client order id, fill qty and price, fees. Goes only to the order's owner.
11md-publisherBroadcasts book changes to every subscriber. Never learns whose order moved the book.
12Feed (edge)Snapshot, BookDelta, TradePrint, Heartbeat, each stamped with feed_seq. A gap means lost data: resync from a snapshot.
13market-dataThe broker's market data service: live fanout to web, chart history, and the newswire's headlines (stored, served and pushed). Its own database (md-db), separate because the workload is different, not because of an org chart.
14simulatorSynthetic trading firms that keep the book alive 24/7. Uses the same public FIX gateway and feed as everyone else: no backdoor. Prices gap only on news.
15newswireInvents headlines and short stories about the listed companies and publishes them over its own spec (ADR 0006). The simulator trades on them; market-data stores them and passes them on to web. Public, like market data.

Not shown on purpose: ExecutionReports back to the simulator (same shape as #10), and per-service migrations. Cut from the MVP entirely: a second venue, smart order routing, the consolidated tape, and all of post-trade (clearing, custody, settlement). See the ideal end-state diagram.
